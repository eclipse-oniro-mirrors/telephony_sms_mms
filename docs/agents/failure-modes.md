## 快速分诊表

| 现象 | 首查位置 | 对应失效模式 |
|---|---|---|
| 某类彩信整条无法展示，日志有字段解码失败 | 失败字段的解码函数与其调用的基础编码函数 | 「合法形式被判为失败」 |
| 解析畸形 PDU 或彩信时崩溃 | 按输入长度读取、循环的位置 | 「按不可信长度越界」 |
| 段数超过某个阈值的长短消息收不到或无法合并 | 合并函数中的计数变量类型 | 「整数宽度不足」 |
| 恰好达到长度上限的分段被拒绝或越界 | 长度校验常量 | 「容量与上限混用」 |
| 应用传入空参数时进程崩溃 | FFI、NAPI、工具函数入口 | 「指针未判空」 |
| 开机阶段收到的短消息丢失 | DataShare 就绪判断与队列 | 「未就绪期间丢消息」 |
| 发送后应用一直等不到结果 | 发送失败返回路径 | 「发送结果未回调」 |
| 分段记录在数据库中残留 | 段序号校验失败分支 | 「分段记录未清理」 |
| 并发下载或发送彩信时阻塞 | 前端静态计数与锁 | 「前端并发控制失衡」 |
| 同一接口在某一前端行为不同 | 三套前端实现 | 「前端不同步」 |

## 失效模式

### 合法形式被判为失败

**机制：** 字段解码函数或其调用的基础编码函数，把协议允许的特殊形式（零长度字符串、只有结束符、可选参数缺省）当作错误返回 `false`。`DecodeMmsHeader` 对任一字段失败立即中止，整条彩信解码失败。

**识别：** 日志先出现基础编码函数的失败信息，随后出现 `The fieldId[...] decode header fail.` 与 `Decode Mms Header Error.`；问题只在特定发送方或特定运营商的彩信上出现。

**修复：** 对照规范确认该形式合法后，在最底层能区分「合法特殊形式」与「越界或格式错误」的函数中返回成功与空值。修改前搜索该基础函数的全部调用点，确认返回语义变化对每个字段都成立。

### 按不可信长度越界

**机制：** 从输入读出的长度或条目数直接用于读取、循环或分配，没有与剩余长度或协议上限比较。

**修复：** 在使用前加比较，失败返回错误；循环次数设上限。同一编解码文件中的同类读取一并检查。

### 整数宽度不足

**机制：** 段数、段序号、累加计数用 `int8_t` 或其他窄类型保存，取值超过 127 时溢出为负数，比较失败。

**识别：** 问题只在段数、条目数超过某个阈值后出现，阈值与类型范围对应。

**修复：** 改为能容纳取值范围的类型；**同一函数内所有参与比较的计数变量一并检查**，只改其中一个仍会失败。

### 容量与上限混用

**机制：** 缓冲区按 `上限 + 1` 分配以容纳结束符，长度校验却也写成 `上限 + 1`，放过了长度为 `上限 + 1` 的数据；或反之把合法的上限长度拒绝。

**修复：** 长度校验用上限本身，容量用上限加一；用例覆盖上限与上限加一。

### 指针未判空

**机制：** FFI 数组头指针、C 字符串、工具函数的数据指针未判空，应用传入空值即崩溃。用空的 `char*` 构造 `std::string` 同样崩溃。

**修复：** 入口处判空，按参数错误返回；构造字符串前判空。同一文件中其他导出函数一并检查。

### 未就绪期间丢消息

**机制：** DataShare 未就绪时收到的消息没有入队，或入队后就绪事件未触发补处理。

**修复：** 保证「确认后入队」与「就绪后补处理」成对。

### 发送结果未回调

**机制：** 发送路径的某个失败分支直接返回，没有调用发送结果回调。

**修复：** 每个失败返回前回调失败结果，并写故障打点。

### 分段记录未清理

**机制：** 段序号越界、合并失败等分支没有删除 `sms_subsection` 中的记录，后续同引用号的消息合并错乱。

**修复：** 在判定为无效的分支删除该组记录。

### 前端并发控制失衡

**机制：** 前端用静态计数与互斥锁限制并发事务，某条返回路径没有递减计数或没有释放等待。

**修复：** 每条返回路径成对递减计数与唤醒等待；napi 与 taihe 两侧同步修改。

### 前端不同步

**修复：** 修复任一前端时，列出另外两套前端的对应函数逐一核对。

## 根因排查方法

- **从日志文本反查。** 解码失败日志文本在仓内基本唯一，先定位分支，再看调用链上哪一层把失败向上传播。
- **对照规范写最小字节序列。** 解码问题先构造能复现的最小 PDU，再判断是「合法形式被拒」还是「越界」。
- **一个现象对应一条机制。** 候选根因必须能解释触发条件（例如「段数超过某值」「特定发送方」）；解释不了触发条件的，继续查找。
- **同一模式全量搜索。** 类型宽度、判空、边界比较这类缺陷成片出现，修复时对同文件与同目录搜索同类写法，在回复中列出已检查范围。

## 修复反例

| 反例 | 问题 | 正确做法 |
|---|---|---|
| 让 `DecodeMmsHeader` 对字段失败一律跳过继续 | 掩盖真实的越界与格式错误 | 在能区分合法形式的底层函数修复 |
| 在上层吞掉基础函数的失败 | 基础函数语义仍错，其他调用点继续出错 | 修正基础函数的返回语义 |
| 只改一个计数变量的类型 | 同函数内其他计数仍溢出 | 同函数内所有计数一并检查 |
| 用 `上限 + 1` 作为长度校验 | 放过越界长度 | 长度用上限，容量用上限加一 |
| 判空后返回成功 | 调用方误以为处理完成 | 返回参数错误 |
| 在客户端加 URL 允许列表式校验 | 与既有安全边界结论冲突 | 按 `AGENTS.md`「必须停下来找人确认的改动」处理 |

## 回归要求

| 改动类型 | 回归 |
|---|---|
| 解码语义 | 最小字节序列用例：合法特殊形式返回成功，截断与越界返回失败；对应 gtest 目标全绿 |
| 边界与类型 | 用例覆盖空、1、上限、上限加一；段数类覆盖 127、128、255 |
| 判空 | 用例传入空指针，断言返回错误且输出不变 |
| 收发链路 | 失败分支断言回调被调用 |
| 通用 | [`high-risk.md`](high-risk.md)「变更风险矩阵」对应行 |
